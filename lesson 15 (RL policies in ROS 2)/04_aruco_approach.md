# Камера и ArUco: подойти к маркеру

**Цель:** собрать двухуровневое управление — классический регулятор по камере сверху,
RL-политика ходьбы снизу — и отправить робота к ArUco-маркеру одним действием ROS 2.
Результат: ЦАПЛЯ-2 по очереди находит и подходит к четырём маркерам; на машине курса —
4 из 4, без падений, 8.6–21.4 с на маркер.

Проверено там же, где [01_quickstart.md](01_quickstart.md): Ubuntu 22.04 в WSL2, ROS 2 Humble,
opencv-python-headless 4.10.0.84.

## Минимальная теория

Политика ходьбы умеет одно: исполнять команду скорости `/cmd_vel`. Куда идти, она не знает
и узнать не может — в её наблюдении нет ни камеры, ни карты. Значит, нужен уровень выше,
который превращает «подойди к маркеру 2» в поток команд скорости:

```
 камера ──► aruco_detector ──► /detections ──► approach_server ──► /cmd_vel ──► policy_node ──► приводы
 15 Гц       solvePnP:            Detection       действие            10 Гц        ONNX, 50 Гц
             пеленг, дальность                    ApproachTarget
```

Уровни развязаны топиками. `approach_server` не знает, что под ним двуногий, а `policy_node`
не знает, что над ним камера. Поэтому сервер без изменений ведёт и Microduck, а вместо
детектора ArUco можно поставить любой другой — лишь бы он публиковал `Detection` с меткой.
В следующем уроке на это место встанет VLA-модель.

**Детектор.** OpenCV находит четыре угла маркера; по ним и известной стороне квадрата
`solvePnP` восстанавливает положение маркера в оптической раме камеры (x вправо, y вниз,
z вперёд). Из него — пеленг `atan2(-x, z)` и дальность `|t|`.

**Регулятор подхода.** Три состояния:

| Состояние | Когда | Команда |
|---|---|---|
| `SEARCH` | цели нет в кадре дольше 1 с | поворот на месте 0.4 рад/с туда, где её видели последней |
| `APPROACH` | цель в кадре | `wz = 1.2·пеленг`; если пеленг меньше 0.5 рад — ещё `vx = 0.5·(d − stop)·cos(пеленг)`, не больше 0.4 м/с |
| `DONE` | `d ≤ stop + 0.1 м` | ноль, действие завершено успешно |

**Действие, а не сервис.** Подход длится секунды, по дороге нужна обратная связь
(состояние, дальность, пеленг) и возможность отмены — ровно то, для чего в
[уроке 3](<../lesson 3 (actions and services)/README.md>) вводились действия.

## Запуск

Сценарий одной командой — робот, политика, детектор и сервер действия:

```bash
ros2 launch rl_policy_ros aruco.launch.py rviz:=true
```

В RViz2 справа внизу — дисплей «Детектор ArUco»: кадр камеры с обведёнными маркерами,
осями и подписью `id0 3.87m +0deg`.

Одна цель — из второго терминала:

```bash
ros2 action send_goal /approach_target rl_policy_interfaces/action/ApproachTarget "{label: aruco_0, stop_distance: 0.8, timeout: 60}" --feedback
```

Обход всех четырёх:

```bash
ros2 run rl_policy_ros approach_client --ros-args -p use_sim_time:=true -p labels:="['aruco_0','aruco_1','aruco_2','aruco_3']"
```

## Ожидаемый результат

В терминале клиента — по строке на маркер. Замер на машине курса:

```
RESULT aruco_0 success=True final=0.890 elapsed=8.6
RESULT aruco_1 success=True final=0.897 elapsed=10.0
RESULT aruco_2 success=True final=0.899 elapsed=11.4
RESULT aruco_3 success=True final=0.890 elapsed=21.4
```

`final` — оценка детектора: от камеры до маркера. Истинное расстояние по одометрии и
координатам маркера из мира — от центра корпуса, оно на 7–8 см больше, потому что камера
стоит на 13 см впереди центра: 0.965, 0.980, 0.979, 0.966 м. Маркер 3 лежит позади-справа от
маркера 2, поэтому на него уходит вдвое больше времени: сначала поиск поворотом.

В логе детектора — доля кадров с маркерами, раз в 10 с:

```
[aruco_detector]: кадров 147, с маркерами 141
```

## Разбор: зеркальный маркер

Первая версия сцены дала результат, на котором стоит остановиться. Робот дошёл до маркера
0 на 0.85 м — физически почти цель, — но детектор в последний раз видел маркер на «1.82 м»,
а потом за полный круг поиска не нашёл его ни разу, хотя робот стоял в полуметре.

Проверка без ROS — робот ставится на известные расстояния перед маркером:

| Истинная дальность, м | 3.87 | 2.87 | 1.87 | 1.07 | 0.67 |
|---|---|---|---|---|---|
| solvePnP, зеркальная текстура | 4.30 | не найден | 2.29 | не найден | не найден |
| solvePnP, исправленная текстура | 4.05 | 3.00 | 1.89 | 1.08 | 0.68 |

Кадр, на котором маркер «не найден», детектор распознаёт сразу, если его отразить по
горизонтали. Текстура на пластине маркера была наложена зеркально. Издалека размытый
зеркальный узор ещё «вытягивался» коррекцией ошибок словаря в правильный id — но с
перепутанным порядком углов, отсюда дальность на 10–20 % больше. Вблизи узор чёткий, и
коррекция уже не спасает.

Урок из этого общий для всего курса: **сенсор проверяется отдельно от регулятора, на
известных значениях**. Регулятор подхода был ни при чём, и подбирать его коэффициенты под
врущий детектор значило бы чинить не то.

## Контрольные проверки

1. Детекции идут:

   ```bash
   ros2 topic echo /detections --once
   ```

   Поле `label: aruco_0`, `distance` около 4.2 в начальной позе (замер: 4.19; маркер в 4 м
   от центра корпуса, камера на 13 см впереди, а с такого расстояния квадрат маркера —
   13 пикселей, и детектор завышает на ~5 %), `bearing` близок к нулю (замер: 0.022).

2. Действие видно в графе:

   ```bash
   ros2 action list -t
   ```

   Ожидается `/approach_target [rl_policy_interfaces/action/ApproachTarget]`. Команда
   спрашивает демон `ros2`; в WSL курса он дважды зависал, и команда висела вместе с ним.
   Лечение — перезапуск демона, см. [01_quickstart.md](01_quickstart.md).

3. Отмена работает: отправьте цель и через пару секунд нажмите Ctrl+C в терминале
   `send_goal`. Замер на машине курса:

   ```
   message: отменено
   Goal finished with status: CANCELED
   ```

   а в логе сервера — `цель aruco_0 отменена, робот остановлен`.

4. Поиск работает: отправьте робота к `aruco_3` из начальной позы. В обратной связи сначала
   идут `SEARCH` — маркер сзади-справа, — потом `APPROACH`.

5. Подмените детектор: остановите `aruco_detector` и опубликуйте детекцию руками:

   ```bash
   ros2 topic pub -r 10 /detections rl_policy_interfaces/msg/Detection "{label: fake, bearing: 0.3, distance: 3.0}"
   ```

   и отправьте цель `label: fake`. В обратной связи — `state: APPROACH`, а в `/cmd_vel`
   замер дал `linear.x: 0.382`, `angular.z: 0.36` (это 1.2 × 0.3): робот поворачивает влево и
   идёт к несуществующей цели. Серверу всё равно, кто источник детекций.

## Итог

- Иерархия: классический регулятор по камере выбирает, куда идти, RL-политика — как идти.
  Связь между ними — один топик `/cmd_vel`.
- Действие ROS 2 подходит для целей, которые длятся: обратная связь, отмена, таймаут.
- Детектор проверяется на известных значениях до того, как ему доверяют регулятор.
