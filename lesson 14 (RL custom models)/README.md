# Урок 14. RL: свои модели и среды

## Цель

После урока вы делаете собственную задачу обучения с подкреплением целиком: пишете
физическую модель на MJCF, оборачиваете её средой Gymnasium, проектируете наблюдение
и награду, **доказываете замером до обучения**, что среда не врёт алгоритму, ведёте
многочасовой прогон без потери результата и переносите политику на робота.

Главное умение урока — не «обучить PPO», а **не сжечь сутки машинного времени на
дефекте, который ловится за секунды**. Поэтому у каждой главы есть проба из
`rl_toolkit`, а у каждого числа в тексте — команда, которой оно получено.

## Чем этот урок отличается от урока 13

[Урок 13](<../lesson 13 (stable baselines3)/README.md>) даёт основы RL и готовые среды:
`CartPole-v1`, простая среда-достигатель, PPO из коробки. Задача там уже поставлена
правильно, и вопрос стоит один — какой алгоритм и сколько шагов.

Здесь задачу ставите вы, и почти все ошибки — ваши.

| | урок 13 | урок 14 |
|---|---|---|
| модель | нет, среда дана | своя, MJCF, паспорт читается из `MjModel` |
| среда | готовая `gym.make` | своя: `np_random`, `truncated`, марковость, границы `Box` |
| наблюдение | дано | проектируется; каждый штрафуемый канал проверяется пробой |
| награда | дана | реестр именованных членов, свип на градиент, доля в сумме |
| прогон | минуты | часы и ночи: чекпойнты, `VecNormalize`, честная оценка, `resume` |
| перенос | не рассматривается | ONNX, модель актуатора, нода ROS 2 |
| симулятор | нет физики | MuJoCo (в [уроке 8](<../lesson 8 (Gazebo)/README.md>) был Gazebo — он про ROS, не про миллион шагов) |

Прошлая версия этого урока называлась «MuJoCo: машинка с рулём учится парковаться».
Её разбор — 20 дефектов, каждый доказан прогоном — стал источником главы 08 и трека A,
а сама старая среда сохранена побитово как [_legacy_env.py](track_a_car/_legacy_env.py):
пробы трека A сравнивают её с новой и показывают разницу на числах.

## Три трека

Треки независимы: каждый — отдельная задача, отдельный класс награды и отдельный
профиль стоимости. Проходить все три не обязательно, но трек A обязателен — на нём
построена половина примеров глав 02–04.

| Трек | Задача | Класс награды | Железо | Бюджет обучения |
|---|---|---|---|---|
| [A — машинка паркуется](track_a_car/README.md) | заехать между двумя занятыми местами и простоять 0.4 с | **за позу**: потенциал `−(W_DIST·dist + w(dist)·\|dyaw\|)` с `gamma`, шесть именованных членов | CPU, 8–12 сред | полный прогон 3 млн шагов = **16.7 мин** (8 сред, 3002 шаг/с); задача решается на 1.2 млн, дальше плато |
| [B — двуногий учится ходить](track_b_walk/README.md) | 33 кг, 8 приводов, слежение за командой скорости | **за слежение**: относительное ядро `σ = max(0.35·\|cmd\|, 0.07)` + штраф простоя, 6 членов | CPU, 8 сред (на этой же RTX 4060 GPU **медленнее**: 2063 шаг/с на CPU против 741) | 6.5 млн = 30 мин — **ничего**; 26 млн = **2 часа** — ходьба; эталон в `policies/` обучен 60 млн = 4.63 ч |
| [C — дрон-сканер](track_c_drone/README.md) | C1 зависание сырыми винтами, C2 облёт объекта поверх каскадного ПД | **за покрытие**: ценность точки зависит от истории эпизода, карта покрытия в наблюдении | CPU, 8 сред; GPU не нужен — узкое место шаг среды | C2 600 тыс. = **3.29 мин**, C1 1.5 млн = **10.69 мин**; весь трек — **14 минут**, до рабочих политик менее 7 |

Что треки дают на выходе (числа замерены на этой машине; команды — в README треков):

* **A**: **200 из 200** успешных парковок на независимом наборе (95 % ДИ Уилсона
  [98.1, 100.0]), ноль столкновений, ноль таймаутов, средний возврат +101.15 ± 0.29.
  Старая версия урока отчитывалась о 62 % — алгоритм тот же, изменилась только среда.
  Два чекпойнта показательны: задача решена уже на 1.2 млн шагов, а САМЫЙ ПОСЛЕДНИЙ
  чекпойнт (3 млн) хуже предпоследних — 97.5 % против 100 %.
* **B**: эталонная пара `walk_60M.zip` + `.pkl` в [policies/](track_b_walk/policies/):
  20 с без падений, 0.356 м/с при команде 0.4. Плюс ловушка `trap.py` — чужие веса
  с той же сигнатурой живут ×0.60 от «ничего не делать».
* **C**: обе политики в [policies/](track_c_drone/policies/). C2 берёт 85 % покрытия
  за **361 шаг** против **1116** у скриптового облёта; C1 — 20/20 доживших и ошибка
  **0.1667 м** против 78.8 шага и 3.377 м у нулевого действия
  (`cd track_c_drone && python evaluate.py --hover policies/hover --scan policies/scan --episodes 20`).

## `rl_toolkit`: пять модулей

Ядро урока. Каждый модуль собран из конкретных оплаченных ошибок и запускается как
самопроверка — она печатает учебный вывод и заканчивается словом «ПРОЙДЕНА».

| Модуль | Что предотвращает | Ключевое API |
|---|---|---|
| [probes.py](rl_toolkit/probes.py) | обучение по среде, которую никто не мерил: неверные границы, скрытое состояние, штраф за ненаблюдаемое, ложный обрыв, неизвестная цена шага | `probe_shapes`, `probe_action_scale`, `probe_null_baseline`, `probe_reward_terms`, `probe_termination`, `probe_step_cost`, `probe_observability`, `probe_controller_sweep`, `report` |
| [rewards.py](rl_toolkit/rewards.py) | монолитную награду, по которой нельзя сказать, кто сколько платит; член-душитель выше 40 % суммы; член, платящий не за то, чем назван | `Ctx`, `Term`, `RewardRegistry`, `RewardLogCallback`, `report` |
| [diagnostics.py](rl_toolkit/diagnostics.py) | метрику, тождественно равную нулю, и форму платы без градиента («поднял вес 8 → 12 — ничего не изменилось»); недостижимый порог | `sweep_term`, `gradient_report`, `synthetic_rollout`, `periodic_gait`, `null_policy_baseline`, `reachability`, `term_share_table` |
| [curriculum.py](rl_toolkit/curriculum.py) | расписание, которое при `resume` выдаёт максимальную сложность с первого шага (три сгоревших прогона), и трюк, синхронизированный в оценку | `Ramp`, `linear`, `staircase`, `CurriculumCallback`, `explain` |
| [checkpointing.py](rl_toolkit/checkpointing.py) | чекпойнты на некруглых номерах, которых «никто не находит»; веса без парной статистики `VecNormalize`; оценку, съедающую четверть прогона | `steps_to_calls`, `real_checkpoint_step`, `list_pairs`, `find_pair`, `bucketize`, `load_policy`, `make_eval_env`, `setup_callbacks` |

Самопроверки — из каталога урока, все пять сегодня завершились кодом 0:

```bash
cd "lesson 14 (RL custom models)"
python -m rl_toolkit.probes
python -m rl_toolkit.rewards
python -m rl_toolkit.diagnostics
python -m rl_toolkit.curriculum
python -m rl_toolkit.checkpointing
```

Если какая-то печатает не «ПРОЙДЕНА», сначала чините её, а не свою среду: пробы —
измерительный инструмент, и сломанный инструмент даёт зелёный свет на пустом месте.

## Установка и требования

ROS 2 для урока **не нужен**: это чистый Python, физика в MuJoCo, обучение на CPU.

```bash
python -m venv .venv
.venv\Scripts\Activate.ps1          # Windows; Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt     # из корня репозитория
```

Развёрнуто — [SETUP.md](../SETUP.md), раздел про RL-дорожку; версии закреплены в
[requirements.txt](../requirements.txt). Ключевые: Python 3.12.3, `mujoco==3.9.0`,
`gymnasium==1.0.0`, `stable-baselines3==2.4.1`, `torch==2.6.0`, `numpy==2.0.2`.
Все числа урока замерены на Windows 11, 24 CPU, RTX 4060 Laptop.

CUDA-сборка `torch` не требуется: во всех треках стоит `device="cpu"`, и это
не компромисс, а замер — глава [07, §9](07_long_runs.md).

## Честно про бюджеты

Единственный ответ на вопрос «сколько учить» — замерить цену шага у себя
(`probe_step_cost`) и разделить. Разброс от посторонней нагрузки на этой же машине
доходил до 12 раз при неизменном коде, так что чужие числа переписывать нельзя.
Ориентиры, которые из замеров получились:

| Бюджет | Что реально успевается |
|---|---|
| **5 минут** | все самопроверки `rl_toolkit`, пробы трека A (30.8 с), стенд трека C, `demo.py` и `trap.py` трека B. Обучения — только разминка: 150 тыс. шагов трека A (5.0 мин, успехов 0) |
| **час** | весь трек C до рабочих политик и с запасом (14 мин обучения) плюс честная оценка и картинки. Трек B на этом бюджете доходит до границы: 13.0 млн шагов — 79 шагов эпизода, 13.5 млн — 587; повезёт с сидом — увидите перелом, не повезёт — нет |
| **ночь (8 ч)** | трек B: 2 часа до ходьбы (26 млн шагов, 20/20 без падений, 0.356 м/с при команде 0.4), остальное — полировка походки. Либо полный прогон трека A с честной оценкой на 200 эпизодах |

Отдельно назовём то, чего урок **не** обещает. Трек A на отгружаемом бюджете
парковаться не научился: разрешимость подтверждена геометрией (требуемый путь 3.03 м
против бюджета 8.43 м за эпизод), а не демонстрацией. Трек B без двух часов не даёт
ничего: на первых 13 млн шагов длина эпизода равна ровно пассивным 53.0 на всех
тринадцати точках оценки — это не поломка, это форма кривой.

## Проверки

1. Все пять самопроверок `rl_toolkit` завершаются словом «ПРОЙДЕНА» и кодом 0.
   Сломанная проба опаснее сломанной среды: она даёт зелёный свет на пустом месте.
2. `cd track_a_car && python probe.py` заканчивается строкой «Все пробы зелёные.
   Можно запускать train.py» (на этой машине — 30.8 с).
3. Вы назвали **пассивную базу** своей задачи в шагах и в секундах и записали её
   рядом с графиком обучения. Для трека B это 53 шага = 1.06 с, для трека A —
   возврат −4.892 за эпизод.
4. Вы померили цену шага своей среды (`probe_step_cost`) при закрытых лишних окнах
   и перевели свой бюджет в шаги. Числа из таблиц урока для этого не годятся.
5. Для каждого члена своей награды выписано, из каких индексов наблюдения выводится
   штрафуемая величина. Пустая строка — член либо получает канал, либо удаляется.
6. `python tools/check_links.py` из корня репозитория не находит битых ссылок
   в файлах урока.
